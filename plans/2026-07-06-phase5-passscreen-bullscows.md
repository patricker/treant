# Phase 5A — Pass-Screen Primitive + Bulls & Cows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. ONE implementer task (the primitive and the game prove each other — they can't be split), deepest-tier review, critic checkpoint, push. Master-plan Global Constraints + ALL standing program rules apply.

**Goal:** The arcade's first hidden-information capability — a reusable pass-and-play blackout/handoff primitive with per-seat secret views — proven on its cheapest game: Bulls & Cows (the public-domain code-breaking duel; Mastermind's ancestor — never use "Mastermind" in user strings).

## The primitive (reusable — design for Salvo/Ambush later)

- **GameDefinition flag** `hiddenInfo?: boolean`. When set and BOTH seats are human, `GamePlay` interposes a full-viewport blackout between turns: "Hand the phone to {name} — tap when ready 👀" (button, not auto-timeout; must cover the ENTIRE viewport incl. the board and any counters — no peeking; Escape does nothing). vs-AI games skip the blackout (the AI doesn't peek — see engine rules).
- **Per-seat views:** `GameHandle` gains `getBoardFor?(seat: number): string` (falls back to `getBoard()` when absent). `useGameSession` tracks the VIEWING seat (= the seat about to move for pass-and-play; = the human seat vs AI) and feeds the Board the seat-appropriate string. The board string for seat s must contain ONLY what seat s may know.
- **Secret input phase:** hidden-info games may need per-player setup moves (code entry) — these are ordinary engine moves whose UI renders behind the blackout flow like any turn. No new phase machinery: the engine's move surface drives it.
- **Hard rules:** secrets NEVER appear in `get_board()` output for the wrong seat, in the URL, in `legal_moves` strings visible to the wrong seat, or in console logs. `noUndo: true` (undo would replay through secret-setting and leak via the log). The share-URL flow must not encode any seed/secret. Document all of this in ARCADE.md §7b as the hidden-info convention.

## Bulls & Cows (id `bulls-cows`, name "Bulls & Cows", icon 🐂 — NOTE: Snort already uses 🐂 as its emoji fallback; both have real glyphs so no launcher collision, but pick 🎯 for Bulls & Cows to be safe)

**Rules (public domain, cite the Wikipedia Bulls and Cows page):** each player sets a secret code (default: 4 distinct digits 0–9); players alternate guesses; feedback per guess = bulls (right digit, right place) + cows (right digit, wrong place). First to crack the opponent's code wins. If the first player cracks and both have guessed equally often, the second player gets one equalizing guess (verify the equalization rule from the source; if unattested, first-to-crack wins outright — document the choice).

**Engine (`treant-wasm/src/bullscows.rs`):**
- State: two codes (set via code-entry moves), guess/feedback histories. Move encoding: code-set `"set:0123"`, guess `"g:4567"` (Display/parse single-sourced + round-trip). `get_board_for(seat)`: seat's OWN code + both feedback histories + opponent's guesses — never the opponent's code.
- **AI without cheating:** the AI's guess policy operates ONLY on the feedback history (consistent-set search: enumerate codes consistent with feedback received so far; pick the guess maximizing expected information / minimax worst-case bucket — Knuth-style; document the chosen heuristic). Wire it through the standard `weak_move(playouts, topK, temp, seed)` surface: playouts budget caps the candidate evaluation work; topK/temp sample among the best K candidate guesses (this IS the difficulty ladder — Easy samples sloppily from a wide K, Hard plays the information-optimal guess). The AI's own code is set uniformly at random (chance). The treant MCTS manager wraps this as a 1-ply search with the consistent-set evaluator — document honestly in the engine header that this game's intelligence lives in the evaluator, not deep search (the master plan sanctioned exactly this).
- Termination: bounded (codes crack in ≤~10 informed guesses; cap at 20 rounds → the player with more bulls-progress wins, else Draw — document).
- Tests: feedback math (bulls/cows incl. repeated-digit edge cases if repeats enabled — default distinct-only keeps it clean); consistent-set filter correctness; the AI-never-cheats property (its guess distribution must be a function of feedback only — test: two games with different opponent codes but identical feedback histories yield identical candidate sets); round-trip; equalization/cap rules; ai_plays.

**Tile:** knobs `length` 3–5, `symbols` 6–10 (digit range), `repeats` 0/1; presets Classic ⭐ (4 len, 10 digits, no repeats), Quick ⚡ (3/6/no), Expert 🤯 (5/10/yes). Category: Brain-teasers. `hiddenInfo: true`, `noUndo: true`. Board UI: code-entry keypad (own code display toggleable "🙈 hide my code"), guess keypad, feedback history table (bulls 🎯 / cows 🐄 per row — both players' histories visible per the rules), resultFlavor for the cap ending. The pass-and-play flow: P1 sets code (blackout) → P2 sets code (blackout) → alternate guess turns with blackouts. vs-AI: no blackouts, AI code hidden by construction.

**Verification (beyond standards):** Playwright pass-and-play: full two-human game — assert the blackout fully covers the board between turns (screenshot), assert P2's view NEVER contains P1's code string in the DOM (grep the DOM at P2's turn for P1's code — the load-bearing secrecy assertion), play to a crack; vs-AI: play a full game vs Easy and Hard, confirm the AI's guesses converge (Hard cracks in ≤6 for 4-digit), confirm noUndo (no undo button). i18n ×6; audit registered; calibration NOTE: the self-play harness may not fit a hidden-info game cleanly — if the calibrate example can't drive it, document why and hand-set the ladder with the topK/temp rationale (precedent: nim's hand-set exception).
